# АГЕНТ-ЗАКОН ALPHA-FLIP v3.2 — читать перед любым действием

Этот файл — постоянная память проекта. Перед любой правкой кода, конфигов или ресурсов агент обязан свериться с этим законом. Нарушение любого пункта = риск потери денег или падения сборки APK.

## 1. ЗОНЫ ОТВЕТСТВЕННОСТИ (не путать)
- AI Studio (ты, агент): ТВОИШЬ и ПРАВИШЬ файлы внутри проекта. Ты НЕ делаешь git, НЕ коммитишь, НЕ пушишь, НЕ запускаешь npm, НЕ собираешь APK. У тебя нет доступа к GitHub.
- Оператор (Рус): кнопкой экспорта/синхронизации переносит проект в GitHub. Только он.
- GitHub Actions: собирает APK из workflow build-apk.yml. Только там.
- Если сборка упала на GitHub — оператор приносит текст ошибки сюда, ты правишь файл, оператор снова экспортирует. Цикл замкнут так и только так.

## 2. ВЕРСИИ ПАКЕТОВ — НИКОГДА НЕ ВЫДУМЫВАТЬ
- Любой номер версии в package.json брать ТОЛЬКО из реально установленных пакетов в node_modules контейнера. Фантазийные версии (пример: @google/genai@^0.1.1, @capacitor-community/native-biometric) недопустимы — GitHub упадёт с ETARGET.
- НЕ переписывать package.json целиком «на глаз». Править точечно.
- После ЛЮБОЙ правки package.json: просканировать ВСЕ импорты в src/ и сверить каждый внешний импорт (всё что начинается с @, плюс react, react-dom, bip39, bs58, tweetnacl, lucide-react, motion, express, dotenv) со списком dependencies. Ни один импортируемый пакет не должен отсутствовать в dependencies.
- Известные рабочие версии на момент последнего круга: @google/genai ^2.28.0, bs58 ^4.0.1.

## 3. ANDROID-ПАПКУ ПРАВИТЬ ТОЛЬКО ТОЧЕЧНО
- MainActivity держать МИНИМАЛЬНЫМ стандартным Capacitor-классом (наследуется от BridgeActivity, в onCreate только super.onCreate). Никаких самопальных нативных хуков: никаких кастомных WebViewClient, никаких перехватчиков onReceivedSslError, никакой ручной загрузки сертификатов, никаких импортов вне стандартного Capacitor. HTTPS уже включён в capacitor.config.ts, дополнительные хуки не нужны и ломают компиляцию.
- minSdkVersion держать 26 (Android 8.0). Это закрывает keep-awake (23), biometric и preferences с запасом. Не опускать ниже 26.
- compileSdkVersion и targetSdkVersion не трогать без явного блокера сборки. Warning «compileSdk=35 не тестировался AGP 8.2.2» — НЕ ошибка, не трогать, suppress-строки не добавлять.
- namespace, applicationId и appId в capacitor.config.ts должны совпадать (com.alphaflip.solana.bot). Не разъезжать.
- Java/Kotlin версии согласованы на 17 везде в android/ (compileOptions sourceCompatibility/targetCompatibility VERSION_17, kotlinOptions jvmTarget 17). Не ставить 21.
- AGP и версию Gradle не менять без блокера.

## 4. РЕСУРСЫ — ВЕКТОРНЫЕ XML, НЕ PNG
- Агент не умеет создавать бинарные PNG. Иконки приложения делать только как векторные XML + адаптивная иконка (mipmap-anydpi-v26/ic_launcher.xml и ic_launcher_round.xml, drawable/ic_launcher_background.xml и ic_launcher_foreground.xml).
- Тема AppTheme брать платформенную (parent @android:style/Theme.Material.Light.NoActionBar), не тянуть лишние зависимости которые могут уронить линковку ресурсов.
- colors.xml обязательный companion к теме.
- В build.gradle держать vectorDrawables.useSupportLibrary = true.
- Перед экспортом проверить что AndroidManifest ссылается только на реально существующие ресурсы (@mipmap, @style, @xml, @raw). Ссылка на отсутствующий ресурс роняет AAPT2.

## 5. ПРИНЦИП ОДНОЙ ПРАВКИ (главный закон против галлюцинаций)
- Чинить ТОЛЬКО блокер сборки. Не «улучшать попутно», не рефакторить соседние файлы, не добавлять eslint/стили/архитектуру если их не просили.
- Каждая лишняя правка = новый риск что агент выдумает несуществующий API или уронит чужую зависимость.
- Warning ≠ ошибка. Deprecated-плашки (Node 20, setup-java v4, ubuntu-latest), package-атрибут в манифесте («value is ignored»), compileSdk 35 — это шум, их НЕ трогать пока они не роняют сборку.
- Мержер манифеста и npm падают на ПЕРВОМ конфликте и не показывают остальные. Поэтому после каждой правки блока — новый экспорт и новый лог, а не «починю всё сразу».

## 6. ФОРМАТ ПРОМПТОВ ОПЕРАТОРУ
- Один промт = один цельный блок без вложенных рамок кода внутри. Иначе markdown рвёт текст и оператор не может скопировать одной кнопкой.
- Содержимое файлов внутри промта давать голым текстом с явными пометками НАЧАЛО/КОНЕЦ, не оборачивая в тройные кавычки.
- Каждый промт заканчивается требованием ОТЧЁТА одной строкой со списком проверок, чтобы оператор мог сверить что файл реально изменён.

## 7. ПЕРЕД ЛЮБЫМ ЭКСПОРТОМ
- Запустить compile_applet и lint_applet. JS/TS часть обязана быть с нулём ошибок.
- Если правка была в android/ — JS не должен пострадать (android-часть не участвует в compile_applet, но убедиться что src/ цел).
- Оператор экспортирует только после зелёного отчёта агента.

## 8. СБОРКА APK И ТЕСТ
- Для первого теста всегда брать app-debug.apk. Debug подписывается автоматически.
- Release-APK без dev-keystore в секретах GitHub выйдет неподписанным и телефон его не примет. Release собирать только когда оператор положит ключ подписи в секреты.
- Workflow build-apk.yml имеет fallback assembleRelease assembleDebug || assembleDebug — если release падает на подписи, debug пересобирается и шаг всё равно зелёный. Это норма, не баг.
- Тестировать ТОЛЬКО на тестовом кошельке с 0.1–0.2 SOL, никогда на основном.

## 9. ЕСЛИ АГЕНТ СОМНЕВАЕТСЯ
- Не знать точную версию пакета или API плагина — лучше сказать оператору «не уверен, нужен лог», чем выдумать. Выдуманная версия роняет GitHub, выдуманный нативный хук роняет компиляцию.
- Любое «я добавлю это заодно» запрещено без явного запроса оператора.
